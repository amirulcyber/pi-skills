# Danvk (danvk.org)

Specimen: *Mapsnap: Automated Georeferencing for Historic Sanborn Maps*
(~11,000 chars body). Read in full 2026-09-17.

## Voice markers

- Curiosity as engine, stated plainly: "could a computer do this?"
- Tours one concrete artifact line by line before any abstraction: red is
  brick, the Bakery at 50 Oak Street, "the Italian Marionette Theatre
  (sounds fun!)". The aside in parentheses does more charm work than any
  adjective could.
- Reports the failed shortcut before the real method: tried Claude/ChatGPT
  first ("It didn't work as well as I'd hoped"), then built the program.
  The failure justifies the build.
- Qualified victories only: "the answer is a qualified 'yes.' ... it
  doesn't get everything right, but it generally does a good job."
- Tool choices justified like a friend: EasyOCR "because it was, well,
  easy to set up, but it also performed well."
- Admits scope creep with humor: "going deeper on this problem than I ever
  intended."

## Structure

Personal curiosity → artifact tour (with pictures) → history detour →
tedium ("increasingly tedious and time-consuming") → automation question →
failed shortcut → method, step by step. The reader wants the tool built
because they felt the boredom first.

## For the house blend

- Tour the evidence before explaining the fix.
- Report the shortcut that failed; it earns the method.
- Qualify the victory out loud.
